# gemgem Harness Engine

AI 영상 제작의 전체 파이프라인을 자동 조율하는 스킬입니다.

## 실행 모드

이 스킬은 3가지 모드로 동작합니다. 사용자의 요청에 따라 자동 판별합니다.

### 모드 1: Full Pipeline (전체 실행)
사용자가 이미지 + 의도를 제공하면 전체 파이프라인을 순차 실행합니다.
외부 API 호출이 필요한 단계에서는 사용자에게 지시를 주고 결과를 기다립니다.

### 모드 2: Evaluate Only (평가만)
사용자가 이미지 또는 영상 프레임을 "평가해줘"와 함께 제공하면
평가만 수행합니다.

### 모드 3: Prompt Only (프롬프트 생성만)
사용자가 "프롬프트만 만들어줘"와 같이 요청하면
분류 + 프롬프트 생성만 수행합니다.


## Full Pipeline 실행 절차

사용자가 이미지를 첨부하고 영상 제작을 요청하면, 아래 순서를 **반드시** 따릅니다.
각 단계를 건너뛰지 않습니다.

---

### STEP 1: 입력 분류

첨부된 이미지와 사용자 의도를 분석하여 유형을 판정합니다.

**분류 규칙:**
- 이미지 1장 + 인물 중심 → `Type A (인물)`
- 이미지 2장 + 합성 의도 (합치다, 넣다, 입히다, 차고 있는, 들고 있는) → `Type B (합성)`
- 이미지 1장 + 물건 + 효과 키워드 (폭발, 불, 물, 연기, 반짝) → `Type C (효과)`
- 이미지 3장 이상 또는 스토리/시퀀스 키워드 → `Type D (스토리)`

**출력:**
```
📋 입력 분류 결과
━━━━━━━━━━━━━━━━
유형: Type X (이름)
근거: (판정 이유)
이미지 도구 추천: (나노바나나 / 이미지 보정 / 배경제거)
영상 모델 추천: (Seedance / Kling)
```

---

### STEP 2: 이미지 분석

첨부된 이미지를 Claude Vision으로 분석합니다.
기록할 항목:
- 피사체 식별 (인물/물건/풍경)
- 조명 방향, 색온도
- 배경 상태
- 해상도/구도 적합성
- 잠재적 문제점

---

### STEP 3: Pre-processing 프롬프트 생성

`references/prompt_templates.md` 파일을 읽고, 유형에 맞는 프롬프트를 생성합니다.

**반드시 6개 차원으로 분리하여 작성합니다:**
```
[SUBJECT] 피사체 설명
[ENVIRONMENT] 배경/환경
[PALETTE] 색감 범위 + 금지 색상
[LIGHTING] 조명 방향/강도
[CONSTRAINT] 금지 요소
[TOOL_NOTE] 도구별 주의사항
```

생성 후, 사용자에게 다음을 지시합니다:
```
🔧 다음 단계: 이미지 생성
━━━━━━━━━━━━━━━━━━━━━━━━
위 프롬프트를 [도구명]에 입력하고, 이미지와 함께 업로드하세요.
결과 이미지를 여기에 첨부해주시면 평가를 진행합니다.
```

---

### STEP 4: Pre-eval (이미지 평가)

사용자가 결과 이미지를 첨부하면, `references/eval_criteria.md`에 정의된
유형별 체크리스트로 **엄격하게** 평가합니다.

**평가 원칙:**
- 관대한 평가 금지. 의심스러우면 FAIL.
- 각 차원을 0.0~1.0으로 채점. 0.7 미만은 FAIL.
- 하나라도 FAIL이면 전체 FAIL.

**PASS 시:**
```
✅ Pre-eval PASS
━━━━━━━━━━━━━━━
(차원별 점수)

→ STEP 5로 진행합니다. 아래 모션 프롬프트를 [영상모델]에 입력하세요.
```

**FAIL 시:**
`references/retry_modifiers.md`에서 실패 항목에 해당하는 수정 문구를 찾아
원래 프롬프트에 추가한 수정 프롬프트를 제시합니다.

```
❌ Pre-eval FAIL (시도 N/3)
━━━━━━━━━━━━━━━━━━━━━━━━━
실패 항목: (항목명 + 이유)

🔄 수정된 프롬프트:
(원래 프롬프트 + 수정 문구)

위 프롬프트로 다시 생성해주세요.
```

3회 실패 시 도구 전환을 권고합니다.

---

### STEP 5: 모션 프롬프트 생성

Pre-eval 통과한 이미지에 맞는 모션 프롬프트를 생성합니다.

**규칙:**
- 색감/조명/구도를 절대 반복하지 않음 (이미 이미지에 확정)
- 카메라 동작만 기술
- 금지 동작을 명시

사용자에게 영상 모델에서 생성하도록 지시합니다.

---

### STEP 6: Post-eval (영상 평가)

사용자가 결과 영상 또는 영상에서 추출한 프레임(첫/중간/마지막)을 첨부하면
`references/eval_criteria.md`의 Post-eval 기준으로 평가합니다.

**영상 파일이 직접 첨부된 경우:**
`scripts/extract_frames.sh`를 실행하여 자동으로 프레임을 추출합니다.

**PASS 시:**
```
✅ Post-eval PASS — 영상 완성
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(차원별 점수)
최종 결과: 성공
총 시도 횟수: Pre N회 + Post N회
추정 비용: XXXX원
```

**FAIL 시:**
모션 프롬프트 수정 후 재시도 지시.
이미지는 변경하지 않습니다.

---

### STEP 7: Type D 전용 — 스티칭

모든 장면이 Post-eval을 통과한 후:
1. `scripts/stitch_scenes.sh`로 장면 연결
2. 최종 영상에 대해 cross-scene 평가 수행
3. 색감/밝기 불일치 장면 식별 시 해당 장면만 재처리 지시

---

## 상태 추적

전체 파이프라인 진행 중 현재 상태를 항상 표시합니다:

```
📊 현재 진행 상황
━━━━━━━━━━━━━━━━
유형: Type B (합성)
현재 단계: STEP 4 (Pre-eval) — 시도 2/3
이미지 도구: 나노바나나
영상 모델: (아직 미진입)
누적 비용: ~160원
```

---

## 비용 계산

각 단계에서 비용을 누적합니다:
- 나노바나나: ~50원/회
- 배경제거/보정: ~10원/회
- Seedance: ~2,100원/회
- Kling: ~1,500원/회
- Claude Vision 평가: ~30원/회

---

## 참조 파일

상세 기준은 references/ 디렉토리의 파일을 읽습니다:
- `references/prompt_templates.md` — 유형별 프롬프트 템플릿 + 예시
- `references/eval_criteria.md` — 평가 체크리스트 상세
- `references/retry_modifiers.md` — 실패 항목별 수정 문구 사전
